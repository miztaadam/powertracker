# Grit (repository name: powertracker)

Grit is a private, offline lifting logbook with a rules-based coach. It is two apps for one product:
an Android app, and a web app (iPhone-first, also used in Chrome on Android). Both share the same
coach and maths. It is built for its owner, who uses it on an iPhone and an Android phone.

The app is called Grit. The repository, the Gradle modules and the Android id `com.powertracker`
keep the old name. Do not rename them: installed data would be orphaned (see `README.md`).

## Folders

| Path | What it is |
|---|---|
| `app/` | The Android app (Kotlin, Compose, Room). |
| `domain/` | The shared coach and maths (Kotlin Multiplatform), used by Android and compiled to JavaScript for the web. |
| `web/` | The web app (React, Vite, offline PWA). Its notes are in `web/README.md`. |
| `web/src/domain/generated/` | JavaScript built from `domain/`. Generated: never edit by hand. |
| `docs/next-update.md` | The running notes: owner decisions, release results, limits, open follow-ups. Read the latest entry first; add to it. |
| `docs/design/` | The design system (`DESIGN.md`) and the committed screenshots of both apps. |
| `docs/manual-checks.md` | Every phone check ever written, by feature. The ten for each release are in `README.md`. |
| `docs/library/` | Exercise guide sources. `sources.md` is generated by a test: do not edit by hand. |
| `docs/superpowers/` | Earlier specs and plans. History; leave alone unless asked. |
| `tools/` | One script that renders the mode-switch sounds for both apps. |
| `.github/workflows/tests.yml` | CI. It runs the Kotlin tests and the web tests, but not the timing checks. |

Nothing here is a separate project. `app/` and `web/` are the same product, so a feature or fix
usually has to be considered for both.

## Working rules

- **Ask before anything that publishes.** Here that means pushing or merging to `main` (the live web
  app updates from it) and handing over a release APK. The owner approves each one by saying
  "publish". Work on a branch until then.
- **Never do anything destructive or irreversible without asking:** deleting data or files, force-pushing,
  rewriting history, rolling the live site back, uninstalling apps.
- **Never roll the web app back below 1.17; fix forward.** An older copy would misread a newer log
  (`docs/next-update.md`, search "fix forward").
- **Never commit secrets or machine-local files.** Already ignored: `local.properties`, `.idea/`, `*.iml`,
  `build/`, `.gradle/`, `.kotlin/`, `web/node_modules/`, `web/dist/`, `web/dist-update/`,
  `web/test-results/`, `web/playwright-report/`, `.superpowers/`. Not ignored, so take care: signing keys
  (`*.jks`, `*.keystore`) and `.env` files. No signing key is kept in this repository. Stage files by path.
- **The owner is not a developer.** Explain results in plain words. Say what was checked and what was
  not, and never report something as working on a phone unless it ran on one.

## Versions

Both apps carry the same version and are bumped together, every release:

- Android: `versionName` and `versionCode` (one higher each release) in `app/build.gradle.kts`.
- Web: `version` in `web/package.json` (and `web/package-lock.json`).
- A web unit test fails if the two disagree (`web/src/screens/settings/appVersion.test.ts`).
- Settings prints the version, so the six Settings screenshots of each app are re-shot. Android:
  `./gradlew :app:testDebugUnitTest --tests '*ScreenshotTest*' -Pscreenshots.update=true`. Web, from
  `web/`: `UPDATE_SCREENSHOTS=1 npm run e2e -- --trace off`. Commit only the Settings shots that changed.
- Add the release to `docs/next-update.md`. Put its one phone check in item 10 of `README.md`'s "Phone checks after a
  release" (replacing the last release's), and its detailed checks in `docs/manual-checks.md`.

Commit `11fa8c1` is a complete example of a version bump. A test-only or notes-only change needs no bump.

## Checks before calling anything done

Kotlin, from the repository root (two separate runs, as CI does; about 11 minutes together):

- `./gradlew :domain:allTests`
- `./gradlew :app:testDebugUnitTest`
- `./gradlew :domain:checkWebDomain` (fails if `web/src/domain/generated/` is out of date)

Web, from `web/` (after `npm ci`):

- `npm run typecheck`
- `npm test` (unit tests)
- `npm run build`
- `npx playwright test --trace off` (all browser tests; about 12 minutes; emulates an iPhone)
- `E2E_UA=android npx playwright test --project e2e --trace off e2e/backCloses.spec.ts <other specs>`
  (the same tests as an Android phone; the spec list is in `.github/workflows/tests.yml`, the web job's last test step)
- `npx playwright test --project=speed --no-deps --trace off` (the timing checks, alone)

There is no linter in this repository. CI runs on pull requests and pushes to `main`, and by hand on any branch
(the workflow's "Run workflow", or `gh api -X POST repos/<owner>/<repo>/actions/workflows/tests.yml/dispatches -f ref=<branch>`).
It runs everything above except the timing checks (`--project=speed`): run those yourself. On a push to `main` it
reports after the live site has updated, so it does not replace the checks on merged main before the push.

## Releasing

1. Finish on a branch with the checks above passing, and a version bump if the app changed.
2. Tell the owner what changes, what was checked and what was not. Wait for "publish".
3. Merge into `main` locally (`git merge --no-ff`), and run the full checks on the merged result.
   If anything fails, do not push.
4. **Web:** push `main`. The live site, https://grit-jet.vercel.app, updates a minute or so later.
   Other branches get a private preview build. (Observed; the hosting settings are in Vercel, not in
   this repository. `web/vercel.json` only sets headers.)
5. **Confirm the web release:** fetch `/`, find the `assets/index-*.js` file it names, and check that
   file contains the new version. Check `/sw.js` lists that file and is served with
   `cache-control: no-cache`.
6. **Android:** `./gradlew :app:assembleRelease` writes
   `app/build/outputs/apk/release/app-release-unsigned.apk`; `output-metadata.json` beside it shows the
   version. The APK is unsigned. There is no app-store upload set up.
7. Record the result in `docs/next-update.md`.

## Good to know

- **After changing `domain/`:** run `./gradlew :domain:syncWebDomain` and commit the generated files.
- **Browser tests run in Chromium only**, emulating an iPhone 13 with Safari's user agent, so the app
  takes its iPhone paths. `E2E_UA=android` switches to Chrome on Android's. Real Safari and real phones
  are never tested here: that is what the owner's ten phone checks in `README.md` are for (the full list is
  `docs/manual-checks.md`).
- **One Playwright run at a time.** It uses fixed ports 4173, 4174 and 4175.
- **Timing-sensitive tests.** A dialog starts listening for Escape and Back just after it is drawn. A
  test that sends either must first await `dialogListening` or `menuListening` (`web/e2e/helpers.ts`).
  When a test fails only under load, find the cause; do not add retries or longer timeouts.
- **Back on a phone** closes the open dialog two ways: `closeRequests.ts` (Android) and
  `historyCloses.ts` (iPhone and iPad), both in `web/src/ui/components/`. The router and the
  screens that use Back for their own steps make their history calls through `historyCloses.ts`; keep it so.
- **Nothing leaves the phone.** The Android app removes the internet permission, and the web app's
  headers allow connections to its own address only. Do not add network calls.
- **Tools that work here:** JDK 17 or newer (CI uses 21), Android SDK platform 37 via `local.properties`,
  Node 22 (no version is pinned).
- **If Maven Central answers HTTP 429** on a first download, rerun with `--max-workers=1`.
- **Cloud sessions only:** Chromium is pre-installed; never run `playwright install`, and keep `--trace off`.
