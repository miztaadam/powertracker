# Version 1.12.2, a tidy-up: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three items from the open follow-ups, which the owner approved on 2026-11-18 ("go ahead"):
1. A failed plan write on Android no longer crashes.
2. After a failed own-exercise save, what you typed is kept.
3. Two text wraps on narrow phones are fixed, and nothing is dropped.

**Tech Stack:** Kotlin, Compose, Robolectric; React 18, vitest, Playwright.

## Global Constraints
- **Same message as 1.12.1:** "Couldn't save — try again." in the screen's snackbar. `CancellationException` is rethrown, and no other failure is swallowed silently.
- **No label changes:** "Sound + vibrate" and the exercise names keep their exact text, and nothing is cut short with an ellipsis or hidden.
- **Unchanged:**
  - what is stored on success;
  - haptics on success;
  - the picker and its 100 ms speed checks;
  - the text-room floors from 1.11 (picker 309, tab 311, plan builder ticked rows 360; web tab under 320 px).
- **Existing tests** pass unedited. List any that changed, each with its reason.
- **Screenshots:** only shots of the changed layouts may change. Put back the known web noise (form-guide, exercise-guide-actions, today, today-rest). List the shots that changed.
- **Fixed rules:**
  - no model names in code or commit bodies;
  - new commits only;
  - stage files by path;
  - never commit `.claude/`, `CLAUDE.md` or `.superpowers/`;
  - e2e with `--trace off`;
  - both apps' versions agree;
  - `git fetch` before any merge.

## Review Focus
1. Every Plan write on Android (`add`, `save`, `delete`, `move`, `setBaseline`) catches a failure and shows the message.
   - After a failed **Add** the form stays open with its numbers, and the double-tap guard is released, so a second **Add** works.
   - `move`: report whether it is one repository transaction. If it is two writes, make a failure leave no half-moved order in storage.
2. **Everything the create form held** (name, category, parent lift, muscles) survives the failure, on both Plan's Add and Today's **Add exercise**.
   - The message is visible while the list or form is open, not hidden behind a dimmed background.
   - A successful save still starts empty next time.
3. "Sound + vibrate" fits on one line from 320 px (web) and from 320 dp of room (Android, if it wraps there too), at no smaller than 12 sp/px. The two plan-builder names never break between letters at 320 dp × 1.3; a break at a space or right after the hyphen in "Chest-supported" is fine.
